# Dashboard Creation with Large Datasets

I've been working as a Power BI developer and BI analyst for the past 8 years, focusing on building end-to-end business intelligence solutions. My experience extends from gathering requirements and designing data models to developing, optimizing, and deploying a wide range of reports and dashboards. I've also implemented security measures like Row-Level Security (RLS) to ensure data confidentiality and compliance.

---

## Experience Building Power BI Dashboards

My work in Power BI has always been about more than just visuals; it's about delivering actionable insights that drive business decisions. I approach each project with a focus on usability, performance, and scalability.

- **From Concept to Deployment:** I've worked on the full lifecycle of BI projects. At **Northside Hospital**, for example, I partnered with clinical teams to create custom operational scorecards that provided real-time throughput monitoring. This wasn't just a dashboard—it was a tool that directly helped reduce patient care delays. At **Manhattan Associates**, I developed over 20 advanced Power BI dashboards for IT and operations, which significantly improved cross-departmental data visibility.

- **Optimization and Performance:** I specialize in optimizing performance. A key part of my role at Manhattan Associates was optimizing semantic models and DAX logic to improve report performance and refresh times. This is crucial for user adoption and for ensuring that complex dashboards with many visuals and filters remain responsive.

- **Enhancing User Experience:** I've built dashboards with advanced features like **drill-throughs**, **bookmarks**, and custom visuals to create a more interactive and user-friendly experience. At **Hiscox Insurance**, I developed an underwriting and claims dashboard that used these features to enhance fraud detection and accelerate decision-making cycles.

## Types of Datasets

I've worked with a wide variety of datasets from different sources, including:

- **Structured Data:** From relational databases like **SQL Server**, **Azure SQL**, and **Oracle**. For example, I built data ingestion pipelines from these sources at Manhattan Associates to streamline data consolidation.

- **Semi-Structured & Cloud Data:** This includes ingesting data from cloud-based systems like **Jira** and **ServiceNow**, as well as working with platforms like **Snowflake** and **SharePoint**.

- **Unstructured Data & Files:** I have experience handling flat files and data lakes, which often require significant transformation before being used in a BI solution.

Similarly, my recent work with **Microsoft Fabric** and **OneLake** at Manhattan Associates involves architecting scalable BI solutions that are built to handle and process immense datasets efficiently. ## Experience with Large Datasets

As a seasoned BI developer, my experience with large datasets goes beyond simply connecting to them. My focus has been on architecting solutions that can handle massive data volumes while maintaining performance for end-users.

### Costco

At Costco, I worked with on-premises and legacy systems, which often meant dealing with data in a less-than-optimized state. The ETL/ELT pipelines I built using Azure Data Factory and Databricks were specifically designed to migrate and process terabytes of retail data. This involved handling massive volumes of transactional data, including:

- Daily sales data
- Inventory levels across multiple warehouses  
- Customer purchase history

For a company of that size, these datasets can easily accumulate to hundreds of terabytes or even petabytes over a few years. My work was to not only move this data to the cloud but to transform it efficiently so that it was ready for analysis and reporting.

### Manhattan Associates

In my current role, the focus on scalability is even more pronounced. Using Microsoft Fabric and OneLake allows me to architect solutions without worrying about the underlying infrastructure limitations. OneLake serves as a unified data hub, letting me connect to diverse data sources and build BI solutions on a single, massive dataset.

The data I work with here from sources like Jira and ServiceNow, when combined with enterprise data from Oracle, can also quickly scale into the terabytes. The core challenge is no longer just processing the data, but making sure a dashboard querying billions of rows remains responsive for the business user, which requires:

- Advanced DAX optimizations
- Efficient data modeling techniques
- Strategic use of aggregations and incremental refresh

## Summary

In short, my experience is less about the absolute number of terabytes and more about the practical challenge of making that data usable and fast for end-users, regardless of its size.
